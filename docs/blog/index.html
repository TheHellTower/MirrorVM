Research roadmap

Development milestones

Each release is a small checkpoint: add a capability, record evidence, and leave open questions visible.

  1. ✓

    M1 - First protect-and-rewrite path

    Convert a linear arithmetic and string method subset, execute it through the shared VM, and leave unsupported methods unchanged with a reported reason. The protected sample passed all 26 configured runtime matrix entries in x86 and x64 processes.

  2. ✓

    M2 - Numeric values end to end

    Carry signed and unsigned integers, native integers, Single, and Double through arguments, constants, arithmetic, conversions, and typed returns. Implement arithmetic, bitwise, shift, comparison, ckfinite, and the full CIL conv.* family, including checked unsigned-source forms. CLR differential checks for implemented numeric opcodes and protected numeric methods passed all 26 configured matrix entries in x86 and x64 processes. Decimal is supported by value only; its arithmetic operators compile to calls.

  3. M3 - Control flow

    Translate branches and build enough control flow, branch targets, stack merges, and validation to run methods with decisions, loops, and switches.

  4. M4 - Method calls and dispatch

    Add call, callvirt, and object creation with argument and return handling. Cover overloads, virtual and abstract methods, interface dispatch, structs, generic methods/types, and the constrained. and tail. prefixes.

  5. M5 - Exception handling

    Translate exception regions, including nested catch, filter, finally, and fault clauses, then verify exception propagation, rethrow, and stack unwinding.

  6. M6 - Toward broad CLR compatibility

    Cover the remaining type system and CIL rules: Boolean and character values; every signed and unsigned integer width; native integers; floating point; Decimal, Half, Int128, and UInt128; enums; references, strings, objects, and boxing; nullable and arbitrary structs and layout; arrays of every rank; generics; managed byrefs/ref returns; unmanaged and function pointers; typed references; unsafe code; and async/iterator state machines. The final gate is the full version matrix below. Every milestone remains open until its behavior is built and run on every applicable target.

Current boundaries

Known limitations

Unsupported methods keep their original bodies and are reported with a reason.

  • Method shapeOnly static, non-generic methods without locals or exception handlers, with up to 256 parameters.
  • Signature typesBoolean, built-in integers through 64-bit, IntPtr/UIntPtr, Single, Double, Decimal, and String.
  • InstructionsLinear argument loads, I4/I8/R4/R8 constants, ldstr, arithmetic, bitwise, shifts, comparisons, neg, not, ckfinite, numeric conv.*, nop, and final ret. Calls, branches, fields, arrays, and pointer/byref operations are unsupported.
  • Skipped methodsUnsupported methods remain unchanged with a reported reason. If no method qualifies, no protected output is written.
  • Numeric behaviorThe implemented numeric opcode set passed CLR differential checks on each matrix runtime. Decimal passes by value, but its operators compile to unsupported calls; Half, Int128, UInt128, enums, arbitrary structs, and every legal CIL stack pairing remain outside this milestone.
  • Inputs and runtimeAssemblies with strong-name public keys, mixed-mode assemblies, and native apphosts are rejected. Pass modern .NET apps as managed DLLs; keep MirrorVM.Runtime.dll beside the output.
  • Compatibility evidenceThe protected sample and numeric CLR differential checks passed all 26 configured matrix entries in x86 and x64 processes. Framework 4.x ran on the installed 4.8.1 in-place CLR; those entries do not prove behavior on each historical 4.x runtime separately.

Working premise

Clarity is part
of the design.

MirrorVM is a human-guided, vibecoded experiment in how far AI can help build a small VM. It is intentionally simple for learning and research, not a product. Releases will add narrow capabilities as research checkpoints, with tests and open questions documented so readers can follow how the project develops.
