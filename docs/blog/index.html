Research roadmap

Development milestones

Each release is a small checkpoint: add a capability, record evidence, and leave open questions visible.

  1. ✓

    M1 · First protect-and-rewrite path

    Convert a linear arithmetic and string subset; keep unsupported methods intact and report why they were skipped.

  2. M2 · Numeric conversion end to end

    Translate Int64/UInt64, native integer, and Single/Double constants, arguments, arithmetic, and returns; verify signed, unsigned, checked, and unchecked cases.

  3. M3 · Control flow

    Add branch targets, loops, and stack validation across alternate paths.

  4. M4 · Method calls

    Translate calls and define how arguments and results move between VM methods.

  5. M5 · Exception handling

    Model catch, filter, finally, and fault regions, including exception propagation and stack unwinding.

  6. M6 · Toward broad CLR compatibility

    Grow CIL and runtime coverage and measure it across Framework 2.0–4.8.1 and modern .NET through 10. Full CLR compatibility remains an open-ended research goal.

Current boundaries

Known limitations

Unsupported methods keep their original bodies and are reported with a reason.

  • Method shapeOnly static, non-generic methods without locals or exception handlers; no more than 256 parameters.
  • Signature typesParameters and returns are limited to Int32, UInt32, and String.
  • InstructionsOnly linear argument loads, I4 constants, ldstr, implemented arithmetic, neg, nop, and final ret. Calls and branches are unsupported.
  • Skipped methodsUnsupported methods remain unchanged with a reported reason. If no method qualifies, no protected output is written.
  • Numeric behaviorThe runtime arithmetic helper supports more value kinds than method conversion, but does not implement every CLR numeric or CIL conversion, comparison, bitwise, shift, or verification rule.
  • Inputs and runtimeAssemblies with strong-name public keys, mixed-mode assemblies, and native apphosts are rejected. Pass modern .NET apps as managed DLLs; keep MirrorVM.Runtime.dll beside the output.
  • Compatibility evidenceThe sample ran on Framework 2.0 and 4.8.1, out-of-support Core 3.1, and .NET 9. Other Framework releases and .NET 10 remain unverified.

Working premise

Clarity is part
of the design.

MirrorVM is a human-guided, vibecoded experiment in how far AI can help build a small VM. It is intentionally simple for learning and research, not a product. Releases will add narrow capabilities as research checkpoints, with tests and open questions documented so readers can follow how the project develops.
